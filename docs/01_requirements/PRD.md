## 一、项目概述

### 1.1 项目名称

**智能校园失物招领系统**（Smart Campus Lost and Found System，简称 Smart Campus L&F）

### 1.2 项目定位

基于多模型融合（YOLO11、OCR、CLIP、协同过滤推荐）的智能化校园失物招领平台，实现从信息上报、智能识别、精准匹配到个性化推荐的全流程自动化，提升校园失物找回率与用户体验。

### 1.3 核心价值主张


| 维度            | 描述                               |
| ------------- | -------------------------------- |
| **全流程 AI 驱动** | 从上报、识别、匹配到推荐，全链路智能化处理            |
| **多模态融合**     | 融合视觉识别（YOLO）与文字识别（OCR），全面提取物品信息  |
| **精准语义匹配**    | 引入 CLIP 多模态模型，突破关键词局限，实现图文统一匹配   |
| **智能推荐**      | 五维加权（图像、文本、地点、时间、行为）推荐相似失物，提升找回率 |

## 二、项目背景与痛点

### 2.1 现状痛点


| 痛点          | 描述                           | 影响          |
| ----------- | ---------------------------- | ----------- |
| **信息分散效率低** | 传统方式依赖人工张贴以及频道消息发送，信息分散且时效性差 | 失物找回率低下     |
| **流程繁琐耗力**  | 失主难以快速寻物，拾获者缺乏便捷上报渠道         | 整体流程耗时且体验不佳 |
| **技术趋势**    | 利用 CV 与 NLP 实现自动化是必然趋势       | 需建设智能化平台    |


### 2.2 项目目标

1. **构建智能平台**：集成多种 AI 模型，实现从信息上报到匹配推荐的全流程自动化
2. **智能识别与匹配**：利用 YOLO、OCR 等模型，实现图片自动识别与精准的图文语义匹配
3. **提升找回率与体验**：引入智能推荐系统，个性化推荐物品，显著提升找回率与用户体验
4. **推动智能化管理**：实现校园失物招领工作的智能化、平台化和系统化管理

## 三、系统架构

### 3.1 四层架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        前端展示层 (Frontend)                           │
│   用户交互界面：上传、搜索、结果展示、个人中心等                            │
└─────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        后端服务层 (Backend)                            │
│   用户管理、文件存储、API 接口服务、业务逻辑编排                            │
└─────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        AI 模型层 (AI Models)                           │
│   YOLO11 | OCR | CLIP | 协同过滤推荐系统                               │
└─────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        数据存储层 (Data Storage)                        │
│   用户信息、物品数据、识别日志、用户行为日志                                │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 四大核心 AI 模型


| 模型         | 职责    | 产出                                              |
| ---------- | ----- | ----------------------------------------------- |
| **YOLO11** | 物品识别  | 检测并框选图片中的物品类别（如杯子、钥匙、钱包等）                       |
| **OCR**    | 文字识别  | 提取图片中的文字（校园卡、纸条等），转为结构化文本                       |
| **CLIP**   | 多模态语义 | 将图文映射到同一语义空间，实现“以图搜图”“以文搜图”                     |
| **协同过滤推荐** | 智能推荐  | 五维加权排序：图像 40% + 文本 30% + 地点 20% + 时间 10% + 协同评分 |


> **补充说明**：五维权重比例来源于 PPT。实际落地时可根据业务效果进行 A/B 调参，建议在配置中心做可配置化。

## 四、功能需求

### 4.1 用户端功能


| 模块       | 功能点      | 描述                         | 优先级 | 备注            |
| -------- | -------- | -------------------------- | --- | ------------- |
| **用户管理** | 注册/登录    | 支持手机号或学号登录                 | P0  | 可结合校园统一认证（如有） |
|          | 个人中心     | 我的发布、收藏、消息通知               | P0  |               |
| **失物上报** | 上传图片     | 支持拍照或相册选择，多图上传             | P0  |               |
|          | 填写信息     | 物品描述、丢失/拾取地点、时间、联系方式       | P0  |               |
|          | 自动识别     | 上传后触发 YOLO + OCR，自动填充/补全信息 | P0  | 
| **寻物搜索** | 以图搜图     | 上传图片，基于 CLIP 相似度检索         | P0  |               |
|          | 以文搜文     | 关键词搜索，结合 OCR 提取的文本         | P0  |               |
|          | 筛选条件     | 地点、时间、物品类型、状态等             | P1  |               |
| **结果展示** | 匹配列表     | 相似度排序展示，展示图片、描述、地点、时间      | P0  |               |
|          | 相关推荐     | 底部“相关失物推荐”，基于协同过滤 + 五维加权   | P0  | 
|          | 地图展示     | 丢失/拾取地点在地图上可视化             | P1  | 
| **对接流程** | 联系失主/拾获者 | 站内消息或展示脱敏后的联系方式            | P0  |               |
|          | 状态管理     | 待认领 / 已认领 / 已归还 等状态流转      | P0  |               |


### 4.2 管理端功能（补充）

| 模块   | 功能点  | 描述                | 优先级 |
| ---- | ---- | ----------------- | --- |
| 物品审核 | 审核发布 | 对敏感信息、违规内容进行审核    | P1  |
| 数据统计 | 统计报表 | 发布量、匹配成功率、热门地点等   | P2  |

## 五、非功能需求

### 5.1 性能需求（补充）


| 指标   | 目标                   | 备注        |
| ---- | -------------------- | --------- |
| 图片上传 | 单张 ≤ 5MB，支持 JPEG/PNG | 常见限制      |
| 识别响应 | YOLO + OCR 首屏结果 < 3s | 可根据实际部署调整 |
| 搜索响应 | 接口 P99 < 2s          |           |
| 并发   | 支持百级并发用户             | 校园场景预估    |


### 5.2 安全与隐私（补充）


| 需求   | 描述               |
| ---- | ---------------- |
| 身份认证 | 登录态管理，敏感操作需二次校验  |
| 数据脱敏 | 联系方式等敏感信息按规则脱敏展示 |
| 图片存储 | 访问控制，防止爬虫批量抓取    |


### 5.3 兼容性


| 端    | 要求                                  |
| ---- | ----------------------------------- |
| 移动端  | 适配主流手机浏览器或独立 App（来源：PPT 阶段三“适配移动端”） |
| PC 端 | 支持主流浏览器（Chrome、Edge、Safari 等）       |

## 九、术语表
