# 失物招领系统数据库表结构字典
本系统数据库共包含 9 张核心数据表，分别为用户表、物品分类表、校园地点表、失物信息表、招领信息表、匹配记录表、认领申请表、通知表和审核记录表。系统以用户表为基础，围绕失物发布、招领发布、认领申请、信息匹配、通知提醒和审核管理等业务进行建模。其中，失物信息表和招领信息表是系统核心业务表，匹配记录表用于记录失物与招领信息之间的关联结果，认领申请表用于管理用户认领流程，通知表用于实现消息提醒，审核记录表用于保存后台审核痕迹，从而支撑整个失物招领业务闭环。
## 1. `USER` 用户表

### 表说明
用于存储系统用户信息，包括普通用户、管理员等。

### 字段定义

| 字段名 | 类型 | 键 | 是否为空 | 说明 |
|---|---|---|---|---|
| id | bigint | PK | 否 | 用户主键ID |
| student_no | varchar |  | 是 | 学号/工号 |
| nickname | varchar |  | 是 | 用户昵称 |
| real_name | varchar |  | 是 | 真实姓名 |
| phone | varchar |  | 是 | 手机号 |
| email | varchar |  | 是 | 邮箱 |
| password_hash | varchar |  | 否 | 密码哈希值 |
| avatar_url | varchar |  | 是 | 头像地址 |
| role | varchar |  | 否 | 用户角色，如普通用户、管理员 |
| status | varchar |  | 否 | 用户状态，如正常、禁用 |
| created_at | datetime |  | 否 | 创建时间 |
| updated_at | datetime |  | 否 | 更新时间 |

### 说明
- `role` 用于区分用户身份。
- `status` 用于表示账号状态。
- 与失物、招领、认领申请、通知、审核记录存在关联。

## 2. `ITEM_CATEGORY` 物品分类表

### 表说明
用于存储物品分类信息，支持分类层级管理。

### 字段定义

| 字段名 | 类型 | 键 | 是否为空 | 说明 |
|---|---|---|---|---|
| id | bigint | PK | 否 | 分类主键ID |
| parent_id | bigint | FK | 是 | 父级分类ID |
| name | varchar |  | 否 | 分类名称 |
| sort_order | int |  | 是 | 排序号 |
| status | varchar |  | 否 | 分类状态 |
| created_at | datetime |  | 否 | 创建时间 |

### 说明
- `parent_id` 用于构造分类树，例如“电子产品”下再细分“手机”“电脑”。
- 可被 `LOST_ITEM` 和 `FOUND_ITEM` 引用。

| building_name | varchar |  | 是 | 楼宇名称 |
| place_name | varchar |  | 否 | 地点名称 |
| longitude | decimal |  | 是 | 经度 |
| latitude | decimal |  | 是 | 纬度 |

| audit_status | varchar |  | 否 | 审核状态 |

## 6. `MATCH_RECORD` 匹配记录表

### 表说明
用于记录失物信息与招领信息之间的匹配结果，可用于智能推荐、人工筛选或相似度分析。

### 字段定义

| 字段名 | 类型 | 键 | 是否为空 | 说明 |
|---|---|---|---|---|
| id | bigint | PK | 否 | 匹配记录主键ID |
| lost_item_id | bigint | FK | 否 | 失物信息ID |
| found_item_id | bigint | FK | 否 | 招领信息ID |
| match_score | decimal |  | 是 | 综合匹配分数 |
| image_score | decimal |  | 是 | 图片匹配分数 |
| text_score | decimal |  | 是 | 文本匹配分数 |
| location_score | decimal |  | 是 | 地点匹配分数 |
| time_score | decimal |  | 是 | 时间匹配分数 |
| match_reason | varchar |  | 是 | 匹配原因说明 |
| status | varchar |  | 否 | 匹配状态 |
| created_at | datetime |  | 否 | 创建时间 |
| updated_at | datetime |  | 否 | 更新时间 |

### 说明
- `lost_item_id` 关联 `LOST_ITEM.id`
- `found_item_id` 关联 `FOUND_ITEM.id`
- 用于支持失物与招领信息的关联判断

# 表关系说明

---

## 用户相关关系
1. `USER` 与 `LOST_ITEM`：一对多
   一个用户可以发布多条失物信息。

2. `USER` 与 `FOUND_ITEM`：一对多
   一个用户可以发布多条招领信息。

3. `USER` 与 `CLAIM_APPLICATION`：一对多
   一个用户可以提交多条认领申请。

4. `USER` 与 `NOTIFICATION`：一对多
   一个用户可以接收多条通知。

5. `USER` 与 `AUDIT_RECORD`：一对多
   一个审核人员可以产生多条审核记录。

---

## 分类相关关系
1. `ITEM_CATEGORY` 与 `LOST_ITEM`：一对多
   一个分类下可以有多条失物信息。

2. `ITEM_CATEGORY` 与 `FOUND_ITEM`：一对多
   一个分类下可以有多条招领信息。

3. `ITEM_CATEGORY` 自关联：一对多
   一个父分类下可以有多个子分类。

---

## 地点相关关系
1. `CAMPUS_LOCATION` 与 `LOST_ITEM`：一对多
   一个地点可对应多条失物记录。

2. `CAMPUS_LOCATION` 与 `FOUND_ITEM`：一对多
   一个地点可对应多条招领记录。

---

## 匹配与认领关系
1. `LOST_ITEM` 与 `MATCH_RECORD`：一对多
   一条失物信息可以匹配多条招领信息。

2. `FOUND_ITEM` 与 `MATCH_RECORD`：一对多
   一条招领信息可以匹配多条失物信息。

3. `FOUND_ITEM` 与 `CLAIM_APPLICATION`：一对多
   一条招领信息可以收到多条认领申请。
