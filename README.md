# smart-campus-lnf

智能校园失物招领系统（Smart Campus L&F）是一款专注于高校师生项目定制的现代化、数字化寻物与招领平台。传统的校园失物招领往往依赖线下交接或低效的群聊信息监听，信息容易被淹没且匹配率低下。本系统通过引入定制技术手段（如：基于 AI 的物品图像相似度匹配、LBS 丢失/拾取地点打卡、状态实现）无论是焦急寻找失物的失主，还是热心发布招领启事的同学，都通过本系统快速实现信息对接，用科技推动「物归原主」，打造更多温度的智慧校园。

| 角色 | 成员 | 技术域 | 核心职责 |

| 视觉处理 | 黄道帅 | YOLO 目标检测 | 负责物品的图像级初级提取，保障 YOLO 模型在复杂校园场景下的高召回率 |

## 完整项目生命周期任务拆解

### 阶段一：需求确立与系统架构设计

**阶段目标**：各模块制定并评审详细的技术落地方案与规范，完成原型与建表。

#### 黄道帅（视觉处理）
- **任务**：确立校园常见失物类别（如：借书证、水杯、钥匙、U盘、校园卡等），输出数据采集策略与边界范围方案
- **技术/工具**：Excel 需求梳理工具、思维导图
- **交付物**：《物品类别标签体系(Class-List)》与《YOLO模型数据采集方案》

#### 成小与（文本处理）
- **任务**：针对不可避免的特殊物件（带有学号的纸条、校园卡），设计结构化字段提取的通用规则
- **技术/工具**：正则表达式设计、数据清洗规范设计
- **交付物**：《OCR 文本结构化解析预案》及脱敏样本集示例

#### 荣麟（推荐系统）
- **任务**：设计多模态融合方案与底层打分机制，清晰界定五维特征（图像、文本、距离、时间、协同过滤评分）各自如何转化为量化分值
- **技术/工具**：算法流程图绘制、Python 数学建模逻辑设定
- **交付物**：《CLIP 跨模态向量表示及协同过滤五维打分算法说明》

#### 黄琬淇（后端开发）
- **任务**：梳理整体业务流向，完成数据库（Entity-Relationship）模型设计并编写所有对前台交互的 API 规范文档
- **技术/工具**：MySQL/PostgreSQL, Apifox 或 Swagger
- **交付物**：《数据库表结构字典(DDL)》与初版《RESTful API 协同接口文档》

#### 陈海玲（前端展示）
- **任务**：绘制用户操作链路图，完成小程序登录、上传、首页瀑布流及个人中心的原型图制作
- **技术/工具**：Figma / 墨刀 / Axure 等 UI 设计工具
- **交付物**：《智能招领系统高保真原型交互图》

---

### 阶段二：数据准备与基础框架搭建

**阶段目标**：AI 团队跑通基础测试数据，前后端完成工程初始化以及数据库对接。

#### 黄道帅（视觉处理）
- **任务**：通过网络爬取或实景拍摄，累积数百张基础物品测试图片，并进行第一轮目标边界框人工标定
- **技术/工具**：LabelImg 或 Roboflow 图像在线标注工具

#### 成小与（文本处理）
- **任务**：搭建 OCR 运行本地环境，针对具有中文及特殊字体的样例图像进行识别工具的比对与选型调优
- **技术/工具**：Anaconda, PaddleOCR 或 EasyOCR, Python 基础环境

#### 荣麟（推荐系统）
- **任务**：拉取开源 CLIP 预训练模型，准备基础代码以将其封装为可提炼 Image/Text 向量并可计算 Cosine Similarity 的本地函数集
- **技术/工具**：OpenAI CLIP, PyTorch, NumPy, FAISS (向量检索评估)

#### 黄琬淇（后端开发）
- **任务**：初始化 FastAPI 工程，实现 ORM 数据库连接；并开发完善基础的用户鉴权（如 JWT 登录认证）、及最基础的图片上传存储逻辑
- **技术/工具**：Python FastAPI, SQLAlchemy/Tortoise ORM, Python-jose

#### 陈海玲（前端展示）
- **任务**：利用微信开发者工具完成工程的基础配置；完成基础的路由结构、全局样式设定与 TabBar 的底部导航建设
- **技术/工具**：微信开发者工具, WXSS, WXML

---

### 阶段三：核心算法开发与业务闭环

**阶段目标**：三大 AI 模型训练并输出可调用的计算接口；前后端主链路业务完成闭环开发。

#### 黄道帅（视觉处理）
- **任务**：利用校园采集的数据集系统化训练并精调 YOLO11 模型，追求 mAP（平均精度均值）和实时检测指标达到可用状态，导出并封装单张预测脚本
- **技术/工具**：YOLO11, PyTorch 训练框架, Python 推理代码

#### 成小与（文本处理）
- **任务**：利用 PaddleOCR 提取字符串，通过结合阶段一设计的正则过滤逻辑清洗出杂质，输出如"姓名：XXX，学号：XXX"等结构化 JSON 数据
- **技术/工具**：Python, PaddleOCR 预测封装

#### 荣麟（推荐系统）
- **任务**：实现算法的"五维加权"整合。将输入（图片，文本，位置坐标差，时间差，用户画像）送入协同过滤及排序引擎，输出 Top-K 相似召回列表的核心逻辑引擎
- **技术/工具**：Python，协同推荐矩阵分解，余弦相似度计算库

#### 黄琬淇（后端开发）
- **任务**：针对用户提交的"发布招领/寻找"进行主干代码实现。并且开始在主业务流中集成黄、成、荣三人的模型预测代码，做到：图片上传后 -> 触发 YOLO 检测 -> 触发 OCR -> 落库 -> 触发 CLIP 与五维排序 -> 返回列表
- **技术/工具**：FastAPI 后端业务路由，Celery/异步任务队列 (如果模型推理较慢需要异步处理)

#### 陈海玲（前端展示）
- **任务**：完成拍照上传并绑定 LBS 位置（微信定位服务）页面的开发；开发首页失物/招领瀑布流及详情页结构设计，与后端提供的假数据结合
- **技术/工具**：微信小程序原生开发, 微信地图 API, Axios/wx.request

## 快速开始

### 后端

```bash
cd backend
# 1. 创建数据库并执行 docs/03_database/schema.sql
# 2. 配置 .env
pip install -r requirements.txt
uvicorn main:app --reload --port 8080
```

### 前端

1. 用微信开发者工具打开 `frontend` 目录
2. 在 `project.config.json` 填入 AppID
3. 修改 `app.js` 中 `baseUrl` 为后端地址
4. 开发时勾选「不校验合法域名」
